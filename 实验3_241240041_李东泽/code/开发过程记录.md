# 实验三开发过程记录

本文件记录本次实际发生的辅助开发与验证过程，避免把自动检查写成已经完成的人工审查。

|阶段|输入与辅助工作|发现的问题|实际处理及证据|
|---|---|---|---|
|需求到代码|读取实验二报告和领域类图，生成状态枚举、SQLite结构和服务模块|原设计依赖 Spring Boot/MySQL/Redis，本机没有 Maven，课程建议桌面应用|改用 Python/Tkinter/SQLite；保留商品版本、唯一有效预约、快照、事务、日志等业务约束|
|功能生成|按认证、商品、交易、治理、查询、界面分文件实现|仅按钮限制权限不足；并发预约不能只靠先查再写|服务层验证会话、角色、归属；BEGIN IMMEDIATE + 部分唯一索引|
|测试设计|生成36项业务测试，覆盖正常路径、异常和并发|正常路径不能证明冻结后的恢复和隐私边界|追加8项回归；测试数量由 unittest 实际输出确认|
|风格检查|Ruff 格式化，Pylint 诊断|首轮长SQL字符串、bar变量命名和多余lambda提示|拆分字符串、改为toolbar、直接传递回调；最终原始日志保留在验证材料|
|桌面验证|运行真实Tk窗口并自动切换游客、管理员、卖家界面|首轮屏幕区域截图抓到了前台编辑器，并非应用窗口|改用窗口句柄截图；重新目视检查，提交材料仅保留正确窗口截图|
|构建|使用pyproject.toml、setuptools、build生成wheel及sdist|首轮源码包缺少README提示|补充安装说明和边界，重新构建|

主要功能代码、测试与技术说明由对话式工具辅助生成，再通过执行、检查和修正形成当前版本。
Git 的 implementation 标签代表已经形成的实现基线，不伪装为工具首次输出；后续提交包含新增
回归检查、构建说明和验证材料。没有补造时间更早的“人工修改”提交，也没有声称学生已经逐行审阅。

后续本人审阅时，应特别检查：确认完成的执行角色、举报冻结后取消的业务含义、禁用账号后的
争议恢复规则、金额边界、超时离线补扫策略。发现问题后以真实新提交记录修订。

当前不足：测试并不覆盖每个GUI弹窗；本地数据库不是远程多租户安全边界；图片只保存本地路径；
没有分页。不能把代码风格满分理解为业务没有缺陷，也不能把窗口冒烟检查等同于人工验收。
